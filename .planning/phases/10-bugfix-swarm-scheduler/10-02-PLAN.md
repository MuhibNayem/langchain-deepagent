<objective>
Fix Scheduler persistence deadlock by replacing threading.Lock() with threading.RLock(). The current Lock prevents the scheduler from re-acquiring the lock from within a locked context (e.g., when tick() calls _persist()), which can cause deadlocks in multi-threaded scenarios.
</objective>

  <action>
In scheduler.py, change line 32 from:
```python
self._lock = threading.Lock()
```
to:
```python
self._lock = threading.RLock()
```

RLock (reentrant lock) allows the same thread to acquire the lock multiple times without blocking. This fixes the deadlock that can occur when tick() holds the lock and then calls _persist(), which also tries to acquire self._lock.
  </action>
