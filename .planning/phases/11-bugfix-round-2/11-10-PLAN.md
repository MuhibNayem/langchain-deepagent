From luminamind/events/buffer.py clear_oldest (lines 99-108):
```python
def clear_oldest(self, count: int) -> list[AgentEvent]:
    with self._lock:
        result = []
        for _ in range(min(count, len(self._buffer))):
            event = self._buffer.popleft()  # Removes from front
            result.append(event)
            if event.event_id in self._index:
                del self._index[event.event_id]
        return result
```

The problem: _index stores absolute positions (0, 1, 2, ...) but after popleft() the deque shifts. If the deque was [A, B, C, D] with index {A:0, B:1, C:2, D:3} and we popleft() to get [C, D, E], the indices become wrong — C is now at 0, not 2.

The get() method uses _index directly:
```python
def get(self, event_id: str) -> AgentEvent | None:
    idx = self._index[event_id]
    return self._buffer[idx]  # Wrong if deque rotated!
```

The fix requires updating all remaining indices after a popleft() rotation.

In clear_oldest(), after popleft():
```python
# After removing event, shift all indices down by 1
for eid in self._index:
    if self._index[eid] > 0:
        self._index[eid] -= 1
```

Or better: use a different approach — don't store absolute indices, store event_ids in a deque of event_ids, and look up via binary search on the event_ids list.

Alternative simpler fix: don't store index at all. The replay() method already uses _session_index which stores event_id lists — we can use that instead of direct index lookup.

Actually the simplest fix: since clear_oldest already removes from deque front, update all indices after removing:
```python
# Decrement all indices that point past the removed position
removed_idx = 0  # popleft removes from index 0
for eid in list(self._index.keys()):
    if self._index[eid] > removed_idx:
        self._index[eid] -= 1
```

Or even simpler: use enumerate over buffer instead of index lookup:
```python
def get(self, event_id: str) -> AgentEvent | None:
    with self._lock:
        for event in self._buffer:
            if event.event_id == event_id:
                return event
        return None
```

This O(n) approach is simpler and correct — no index maintenance needed. But if performance is critical, use the index adjustment approach.
